# Cambridge Battlecode 2026 bots

Python bots for Cambridge Battlecode 2026 (event cambc2026a). The deadline is around early November 2026.

## Read first
- `docs/GameRules.md`: the game rules.
- `docs/BotAPIPython.md`: the Python bot API.
- `docs/NEURAL_NET_GUIDE.md`: the agreed design for neural networks in the bot (hybrid: scripted bot, decisions as scoring functions in `decide.py`, small packed-int8 networks swapped in behind them; the first is the 64→32→16→6 mode selector).
- `bots/fuelbench/RESULTS.md`: measured fuel costs in release builds.
- `docs/NEXT_STEPS.md`: the ranked plan after each submission (what to build next and why).
- `docs/REDESIGN.md` and `bots/samit-sucks/README.md`: the redesign started 2026-10-25 (why, the phase plan, what phase 1 measured). `hybrid` stays live until `samit-sucks` beats it.

The 2.2.5-era maps are kept under `maps/old-2.2.5/` for comparison only. `docs/` was refreshed from the handbook's "Download for LLM" page (https://2026a.battlecode.co.uk/game/docs/agents) the same day; patch notes live at /game/patch-notes (JS-rendered: read them in a browser, not with a fetch). Patch 1.0.1 (2026-10-20 20:05 UK) only nerfed Heart of Ruin: strength per shard 5 to 4, focus per shard 15 to 12; a bot that fails to compile after a patch now gets 24 hours before it auto-loses ranked matches. Patch 1.0.2 (2026-10-21, ~01:30 UTC) is balance only: Stellar 750/85 → 650/70, Heart of Ruin strength 40 → 30 (3.5 per shard, landing 1.5x focus), Ren stun 0.75x focus; Vesper Vale 1000 hp / 55 strength, Vendetta 1000 hp, Tavi 900 hp / 110 focus, Prism 1.5 focus per gem. SDK 3.0.4 adds `DistanceField.copy_from`. Engine 1.0.3 went live on 2026-10-22 around 13:00 UTC with cambc 3.0.5 (refreshed the same day: SDK diff is only the debug-drawing lifetime, plus a 40th map, `00road-of-riches`); no 1.0.3 patch notes were published as of 14:00 UTC, so treat band runs before and after it as different conditions (v33's band set is 1.0.2, v34's is 1.0.3). Replay dumps need `python tools/fetch_viewer.py` after every engine bump.
- Submit: `cambc submit bots/hybrid` (needs `cambc login`, typed by Tyler). Tag the commit `hybrid-vN` to match the submission number.
- Run a match: `cambc run <botA> <botB> --map <name> --release`. Bot stdout is inside the `.repl26a` replay (a zip): `team-a.stdout`, `team-a.fuel`.
- Evaluate a change: `python tools/run_matches.py hybrid hybrid@hybrid-v1` plays the working copy against a tagged version on every map from both sides (about 45 seconds for 42 games) and reports wins, gem margins, deaths, fuel exhaustions and stalls. Keep a change only if it wins there, and treat any `exh` as a bug. `name@gitref` exports any tagged version as an opponent. The harness is exactly deterministic: identical code mirrors 40-40 with every map's two games swapped to the gem (checked 2026-10-22, v39 vs itself). So a "switched off" or "no-op" change must mirror exactly against the previous tag before it is called a control; dormant code is not free. The networks run behind `fuel.can_afford` gates, and a few thousand fuel of extra per-turn bookkeeping shifted those gates enough that v41 (v39 plus switched-off cohesion code) lost 30-50 to v39 and the gated variant 36-44.
- Judge a submission on the ladder, not the mirror: `python tools/fetch_ours.py --since <ISO UTC> [--until <ISO UTC>] -o data/replays/ours-vN` fetches, dumps and breaks our ranked games down in one go (or by hand: list our ranked games (`cambc matches list --team me --kind ranked --json`), download each (`cambc matches download <id> -o data/replays/ours-vN/raw/<id>.zip`, one at a time: the platform returns HTTP 409 otherwise), dump them with `tools/replay_dump.py`, then `python tools/ladder_deaths.py data/replays/ours-vN/ladder --index data/replays/ours-vN/raw/index.json`. The zips carry our own `team-a.stdout`.
- Judge behaviour changes against the +200 band, not the mirror: unranked challenges replayed identically for each version (`tools/challenges.py queue --replay-from data/challenges/v14-band200 --limit 14`), compared with `tools/analysis/compare_runs.py`. See `tools/analysis/README.md`.
- Open a replay: `cambc view <replay> --port 7026`, then the printed link in Firefox (Chrome freezes on this PC).
- Train on ladder replays, one folder per game version so a balance patch never mixes rules (`data/replays/<engine>/`): `python tools/fetch_replays.py --teams 100 --per-team 10 --since <patch time, UTC ISO> --won-only -o data/replays/1.0.1/raw`, `python tools/replay_dump.py data/replays/1.0.1/raw -o data/replays/1.0.1/ladder --jobs 6`, `python tools/replay_features.py data/replays/1.0.1/ladder --index data/replays/1.0.1/raw/index.json --winners-only -o data/replays/1.0.1/modes.npz`, then `python tools/train_mode_selector.py data/replays/1.0.1/modes.npz --winners --logit-l2 1e-3`, `python tools/parity_test.py data/replays/1.0.1/modes.npz`, and the harness. Winning sides of strong teams beat volume: the 89-game set with 36% winners scored worse than the 62-game set. Needs Node and `python tools/fetch_viewer.py` once per cambc version. See the README's replay section. The camp scorer (second head) trains from the same dumps: `python tools/replay_camp_dataset.py data/replays/1.0.1/ladder --index data/replays/1.0.1/raw/index.json -o data/replays/1.0.1/camps_all.npz`, `python tools/train_camp_scorer.py data/replays/1.0.1/camps_all.npz --winners --arch bilinear`, then the parity test. Per-candidate hidden layers cost about 10K fuel per lane, so heads that rank a list must be bilinear (`nn.Bilinear`); measure any new network with `bots/fuelbench`, never with the bot's own fuel counter.

## Constraints
- The runtime is CPython 3.13 in WebAssembly. No NumPy, PyTorch or compiled extensions. Pure Python and the stdlib only.
- A champion turn has 2.5M fuel (about 4.5M usable on the first turn). Running out suspends the bot until next round and loses the rest of that turn's actions. An empty Python loop iteration costs about 1,000 fuel; a whole-map `DistanceField` about 80 per tile; `game_map.camp_groups()` plus per-group setup 2 to 3M on the biggest maps, so first-turn work must stay lean.
- Every module except `main.py` is imported at build time, so precompute at module level.
